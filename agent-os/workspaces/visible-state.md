# Visible State

Throughline should leave the user with something they can inspect.

Use Obsidian when the user wants a local visual knowledge base. Use another notes app, a repo `docs/` folder, an issue tracker, or a dashboard when that fits better.

## Setup Questions

Ask during bootstrap:

1. Where should project state live?
2. What should be the single source of truth?
3. Should updates be daily, session-end, milestone, manual only, or disabled?
4. Should HTML updates be private, public, or mixed by workspace?
5. What must never appear in exported updates?

## Minimum State Surface

```md
Current focus:
Status:
Next action:
Open decisions:
Blocked by:
Recent checks:
Recent sources:
Last update:
```

## Rules

- Keep one visible state surface per workspace.
- Link to deep documents instead of duplicating them.
- Keep sensitive details in private notes.
- Let the user change cadence without changing the framework.
- Treat generated HTML as an artifact that may need privacy review before sharing.
